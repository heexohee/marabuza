# 1부 세션 B — 분홍 도트 커서 + 카운터 손님 인내심 게이지 수동 테스트 케이스

**스토리 유형**: Visual/Feel(커서 모양, 게이지 흔들림) + UI
**증거 위치**: `production/qa/evidence/` — 파일명 `part1-<케이스ID>-2026-09-27.png` / 게이지는 연속 캡처 또는 짧은 화면 녹화
**게이트 레벨**: BLOCKING (Visual/Feel은 리드 확인 필요)
**대상 빌드**: 출시 빌드 `dist/` — `http://localhost:8131/self-serve.html`
**창 크기**: 1280×720 (B-09만 1024×640 추가)

> **헤드리스 주의**: 헤드리스 Chrome 스크린샷에는 OS 마우스 커서가 찍히지 않는다. 커서는 화면 캡처가 아니라
> **계산된 CSS `cursor` 값**으로 판정한다. 각 지점에서 CDP `Input.dispatchMouseEvent`(type `mouseMoved`)로
> 마우스를 올린 뒤 아래 스니펫을 실행한다.
>
> ```js
> const at = (x, y) => { const el = document.elementFromPoint(x, y);
>   return { tag: el.tagName, id: el.id, cls: el.className, cursor: getComputedStyle(el).cursor }; };
> ```
> 판정 규칙: `cursor`가 분홍 도트 화살표 이미지 `url(...)`을 포함해야 한다(파일명을 B-01에서 먼저 확인해 기록).
> `pointer`, `default`, `auto`, `text`, 또는 발바닥(paw) 이미지가 나오면 Fail.

## B-01 — 커서 이미지 자체 확인 (기준 잡기)

**사전 조건**: 타이틀 화면.
**단계**:
1. `getComputedStyle(document.body).cursor` 값을 기록하고, 안에 든 `url(...)` 주소를 새 탭으로 열어 이미지를 캡처한다.
2. 페이지의 모든 스타일시트 규칙에서 `cursor` 속성을 모아 목록으로 기록한다.
   ```js
   [...document.styleSheets].flatMap(s => { try { return [...s.cssRules]; } catch { return []; } })
     .filter(r => r.style && r.style.cursor).map(r => r.selectorText + ' → ' + r.style.cursor)
   ```
3. 목록과 `dist/` 파일에서 "paw"/"발바닥" 이름의 커서 이미지가 있는지 찾는다.
**기대 결과**: 커서 이미지는 분홍 도트 화살표 하나. 스타일시트의 모든 `cursor` 값이 같은 이미지(대체값 포함)를 가리킨다. 발바닥 커서 규칙·이미지가 없다.
**판정 기준**: 서로 다른 커서 이미지가 1개뿐이고 paw 규칙 0건이면 Pass.

## B-07 — 카운터 손님 인내심 게이지 위치와 줄어듦

**사전 조건**: 1일차 영업 중, 카운터에 손님 1명 도착.
**단계**:
1. 손님이 카운터에 서자마자 캡처하고 게이지가 손님 얼굴 **옆**에 붙어 있는지 확인한다.
2. 응대하지 않고 5초마다 캡처하며 게이지 길이(요소 폭 또는 `style` 값)를 기록한다.
3. 손님을 응대해 계산을 마치고 게이지가 사라지는지 확인한다.
4. 다음 손님이 카운터에 오면 게이지가 가득 찬 상태에서 다시 시작하는지 확인한다.
**기대 결과**: 게이지는 얼굴 옆에 표시되고 얼굴·말풍선·가격표를 가리지 않는다. 시간에 따라 한 방향으로 매끄럽게 줄어든다(늘었다 줄었다 하지 않음). 계산이 끝나면 사라지고, 새 손님은 가득 찬 게이지로 시작한다.
**판정 기준**: 기록한 길이가 단조 감소하고, 얼굴 겹침 0건, 새 손님 게이지가 최대치로 시작하면 Pass.
**실제 결과**:

## B-08 — 인내심 끝 무렵: 빨간색·흔들림·"빨리요…" 후 떠남

**사전 조건**: B-07 이어서, 카운터 손님을 응대하지 않고 둔다.
**단계**:
1. 게이지 색을 1초마다 기록한다(`getComputedStyle(게이지).backgroundColor`).
2. 게이지가 빨간색으로 바뀐 순간의 남은 비율(대략)을 기록하고 캡처한다.
3. 그때 게이지 또는 손님이 흔들리는지(연속 캡처 3장에서 x좌표 변화, 또는 `animation-name` 값) 확인한다.
4. "빨리요…" 문구가 뜨는지, 두 창 크기 모두에서 말풍선 안에 들어가는지 확인한다.
5. 끝까지 기다려 손님이 떠나는 순간을 기록한다.
6. 빨간 상태에서 급히 응대해 계산하면 정상 판매되는지 확인한다(다른 손님으로).
**기대 결과**: 끝 무렵에만 빨갛게 바뀌고 흔들리며 "빨리요…"가 뜬다(처음부터 빨갛지 않음). 게이지가 0이 되면 손님이 떠난다. 빨간 상태에서도 응대하면 정상 계산되고 흔들림·문구가 사라진다.
**판정 기준**: 빨강·흔들림·"빨리요…" 셋 다 확인, 게이지 0 전에 떠나지 않음, 빨간 상태 응대 시 정상 판매이면 Pass.
**실제 결과**:

## B-09 — 게이지와 "빨리요…" 1024×640 배치

**사전 조건**: 창 1024×640, 영업 중, 카운터 손님.
**단계**:
1. B-07 1단계와 B-08 2~4단계를 1024×640에서 반복하며 캡처한다.
2. 게이지·"빨리요…" 말풍선 요소의 `getBoundingClientRect()`가 창 안(0 ≤ left, right ≤ innerWidth, 0 ≤ top, bottom ≤ innerHeight)인지 검사한다.
3. 흔들리는 동안 페이지 스크롤이 생기지 않는지(`scrollWidth <= innerWidth`) 확인한다.
**기대 결과**: 작은 창에서도 게이지·문구가 창 안에 있고, 흔들림 때문에 가로 스크롤이 잠깐이라도 생기지 않는다.
**판정 기준**: 좌표 검사·스크롤 검사 실패 0건이면 Pass.
**실제 결과**:
**Pass/Fail**:
