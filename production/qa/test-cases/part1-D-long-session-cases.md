## 브라우저 실행 조건

- Chrome 플래그: `--enable-precise-memory-info`(없으면 heap 값이 뭉개짐), `--disable-background-timer-throttling`, `--disable-renderer-backgrounding`, `--disable-backgrounding-occluded-windows`.
- 세션 도중 **새로고침 금지**(새로고침하면 누수 측정이 무효). 한 탭에서 끝까지.
- CDP `Runtime.consoleAPICalled` / `Runtime.exceptionThrown`을 세션 시작부터 기록.

## 측정 도구 (세션 시작 시 한 번 주입)

```js
window.__qa = {
  heap: [],
  frames: [],
  rec: false,
  start() { this.frames = []; this.rec = true; let last = performance.now();
    const tick = t => { if (!this.rec) return; this.frames.push(t - last); last = t; requestAnimationFrame(tick); };
    requestAnimationFrame(tick); },
  stop() { this.rec = false; const f = this.frames.slice(1).sort((a, b) => a - b);
    return { n: f.length, max: f.at(-1), p99: f[Math.floor(f.length * 0.99)], over100: f.filter(x => x > 100).length,
             over50: f.filter(x => x > 50).length }; },
  sample(day) { const m = performance.memory;
    this.heap.push({ day, used: m.usedJSHeapSize, total: m.totalJSHeapSize, nodes: document.getElementsByTagName('*').length });
    return this.heap.at(-1); }
};
```

- heap 측정 직전 CDP `HeapProfiler.collectGarbage`를 2번 호출하고 2초 기다린 뒤 `__qa.sample(day)`.
- DOM 노드 수도 함께 기록(요소가 계속 쌓이는 누수 확인용).

## D-06 — 메모리 추세 판정 (꾸준한 증가 여부)

**사전 조건**: D-01~D-05 측정값이 기록표에 모두 있음.
**단계**:
1. used 값 5개를 순서대로 놓고 이웃 사이 증가량을 계산한다.
2. DOM 노드 수 5개도 같은 방식으로 본다.
3. 28일차 측정 뒤 상점에서 3분 가만히 둔 다음 GC 2회 → 한 번 더 측정한다(대기 중 증가 확인).
**기대 결과**: 28일차 used ≤ 1일차 × 2.0. 다섯 값이 매번 비슷한 폭으로 오르기만 하는 모양(예: +15%, +15%, +15%, +15%)이 아니라 어느 지점에서 평평해진다. DOM 노드 수는 메뉴 추가에 따른 계단 증가 외에 계속 늘지 않는다. 3분 대기 전후 차이 5% 이내.
**판정 기준**: 2.0× 이하 + 네 구간 모두 증가(단조 증가)이면서 마지막 구간 증가율이 첫 구간 이상인 경우가 **아니면** Pass. 단조 증가지만 2.0× 이하이면 CONCERNS로 표시해 heap 스냅샷을 첨부한다.
