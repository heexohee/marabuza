# 상점 화면 정렬 테스트 케이스

**스토리 유형**: UI
**증거 위치**: `production/qa/evidence/` (각 화면/뷰포트 스크린샷을 반드시 저장할 것 — 캡처 후 폐기 금지)
**게이트 레벨**: BLOCKING

> 테스터는 각 케이스마다 해당 상태의 스크린샷을 캡처해
> `production/qa/evidence/shop-alignment-<케이스ID>-<YYYY-MM-DD>.png` 형식으로 저장한다.
> 뷰포트 폭은 브라우저 개발자 도구의 반응형 모드로 정확히 1200px 및 375px로 맞춘다.

## 공통 사전 조건

- 새 게임 시작 → DAY 1 진행 → 마감 후 요약 화면에서 "상점으로 →" 클릭하여 상점 화면 진입

---

## TC-S01 — 가게 업그레이드 카드 표시 (1200px)

**사전 조건**: 뷰포트 폭 1200px, 상점 화면
**단계**:
  1. "가게 업그레이드" 섹션의 카드 4개(냄비 추가, 화력 강화, 인테리어, 좌석 확장)와 노란색 "100g당 가격" 박스를 확인한다
**기대 결과**: 4개의 업그레이드 카드와 가격 박스가 한 행에 나란히 배치되며, 각 카드의 구매 버튼(가격 표시 버튼)이 모두 같은 세로 위치(윗변 정렬)에 놓인다.
**판정 기준**: 5개 요소(카드 4 + 가격 박스)의 구매 버튼/조작 버튼 상단 y좌표가 일치한다 (육안상 층이 어긋나지 않음).

---

## TC-S02 — 100g당 가격 박스 내부 정렬

**사전 조건**: 뷰포트 폭 1200px, 상점 화면
**단계**:
  1. "100g당 가격" 박스를 확인한다: 윗줄에 현재 가격(원), 아랫줄에 "−"/"+" 원형 버튼과 손님 방문 힌트 문구
**기대 결과**: 가격 값이 박스 상단에 표시되고, "−"와 "+" 버튼이 박스 안쪽에 완전히 들어가 테두리를 벗어나지 않으며, 힌트 문구("손님 방문 ×...")가 버튼 아래 한 줄로 표시된다.
**단계 (계속)**:
  2. "+" 버튼을 여러 번 눌러 가격을 최댓값(3,500원)까지 올린다
**기대 결과 (계속)**: 가격이 최댓값에 도달하면 "+" 버튼이 비활성화(disabled) 상태로 바뀐다.
**판정 기준**: −/+ 버튼이 박스 밖으로 삐져나오지 않고, 최댓값에서 "+"가 비활성화된다. (역으로 "−"를 눌러 최솟값 1,500원까지 내리면 "−"가 비활성화되는지도 함께 확인)

## TC-S03 — 재료 사기 카드: 해금 전/후 버튼 2줄 표시

**사전 조건**: 뷰포트 폭 1200px, 상점 화면, 소고기가 아직 잠겨 있는 상태(신규 게임 기본값)
**단계**:
  1. 잠긴 재료(예: 소고기) 카드의 구매 버튼을 확인한다: 첫 줄 "🔓 해금", 둘째 줄 가격(6,000원)
  2. 이미 해금된 기본 재료(예: 청경채) 카드의 구매 버튼을 확인한다: 첫 줄 "+10개", 둘째 줄 가격
**기대 결과**: 두 종류의 버튼 모두 텍스트가 두 줄로 나뉘어 표시되며, 어느 줄도 버튼 바깥으로 잘리거나 넘치지 않는다.
**판정 기준**: 해금 버튼과 구매 버튼 각각에서 두 줄 텍스트가 버튼 경계 안에 완전히 들어간다.

## TC-S04 — 재료 카드 구매 버튼 상단 정렬 (같은 행)

**사전 조건**: 뷰포트 폭 1200px, 상점 화면, "재료 사기" 섹션이 여러 행으로 줄바꿈된 상태(12개 재료 카드)
**단계**:
  1. 같은 행에 놓인 재료 카드들의 구매/해금 버튼 상단 위치를 비교한다
**기대 결과**: 같은 행에 있는 카드들의 버튼이 모두 같은 세로선(윗변)에서 시작한다. 재료명 길이나 잠금 여부가 달라도 버튼 위치가 어긋나지 않는다.
**판정 기준**: 같은 행 카드들의 버튼 상단 y좌표가 일치한다.

---

## TC-S05 — 자금 부족 시 버튼 비활성화

**사전 조건**: 소지금이 특정 재료의 팩 가격보다 적은 상태(예: 재료를 반복 구매해 잔액을 6,000원 미만으로 낮춘 뒤 소고기 해금 시도, 또는 저장 파일로 저잔액 상태를 재현)
**단계**:
  1. 소지금보다 비싼 재료/업그레이드 카드의 구매 버튼 상태를 확인한다
**기대 결과**: 소지금이 부족한 카드의 구매 버튼이 비활성화(클릭 불가, 흐릿하게 표시)된다.
**판정 기준**: 잔액 부족 카드의 버튼에 disabled 상태가 시각적으로 나타나고 클릭해도 반응하지 않는다.

## TC-S06 — 업그레이드 최대 레벨 시 MAX 버튼

**사전 조건**: 특정 업그레이드(예: 화력 강화, 3단계까지 구매 가능)를 반복 구매하여 최대 레벨에 도달시킨 상태
**단계**:
  1. 최대 레벨에 도달한 업그레이드 카드의 버튼을 확인한다
**기대 결과**: 가격 버튼 대신 "MAX" 버튼이 표시되고 비활성화되어 있다. 해당 업그레이드의 단계 표시(pip)가 모두 채워져 있다.
**판정 기준**: 버튼 텍스트가 정확히 "MAX"이고 클릭 불가 상태이다.

## TC-S07 — 하단 푸터 버튼 (타이틀 / 영업 시작)

**사전 조건**: 뷰포트 폭 1200px, 상점 화면
**단계**:
  1. 화면 하단의 "타이틀" 버튼과 "DAY N 영업 시작!" 버튼을 확인한다
**기대 결과**: 두 버튼이 겹치지 않고 나란히 배치되며, "DAY N 영업 시작!"의 N이 실제 다음 날짜(현재 진행한 DAY + 1)와 일치한다.
**판정 기준**: 버튼 텍스트의 N이 다음 영업일 번호와 정확히 일치하고, 두 버튼이 서로 겹치지 않는다.

---

## TC-S08 — 모바일 375px: 업그레이드 카드 줄바꿈

**사전 조건**: 뷰포트 폭 375px, 상점 화면
**단계**:
  1. "가게 업그레이드" 섹션을 확인한다: 카드가 한 줄에 다 들어가지 않아 여러 행으로 줄바꿈되는지 확인
  2. 각 카드 내부의 텍스트(카드명, 설명, 가격)가 잘리는지 확인한다
**기대 결과**: 카드가 화면 폭에 맞게 자동으로 여러 행으로 줄바꿈되고, 카드 내부 텍스트가 잘리거나(overflow) 버튼 밖으로 넘치지 않는다. 가로 스크롤이 발생하지 않는다.
**판정 기준**: 375px에서 가로 스크롤바가 생기지 않고, 카드 내 텍스트가 모두 읽을 수 있는 상태로 줄바꿈된다.

## TC-S09 — 모바일 375px: 재료 카드 및 −/+ 버튼

**사전 조건**: 뷰포트 폭 375px, 상점 화면
**단계**:
  1. "재료 사기" 섹션의 카드들을 확인한다 (텍스트 잘림 여부, 버튼 2줄 표시 여부)
  2. "100g당 가격" 박스의 −/+ 버튼이 박스 안에 들어가 있는지 확인한다
**기대 결과**: 375px에서도 재료 카드 텍스트가 잘리지 않고, 구매 버튼의 2줄 텍스트가 버튼 안에 유지되며, −/+ 버튼이 노란 박스 밖으로 삐져나오지 않는다.
**판정 기준**: 375px에서 텍스트 잘림·버튼 밖 삐져나옴이 하나도 없다.

---

## TC-S10 — 모바일 375px: 하단 푸터 버튼

**사전 조건**: 뷰포트 폭 375px, 상점 화면
**단계**:
  1. 화면 하단 "타이틀" / "DAY N 영업 시작!" 버튼을 확인한다
**기대 결과**: 두 버튼이 375px 폭에서도 겹치지 않고 화면 안에 완전히 들어오며(가로 스크롤 없이), 텍스트가 잘리지 않는다.
**판정 기준**: 두 버튼 모두 뷰포트 안에서 온전히 보이고 텍스트가 잘리지 않는다.
