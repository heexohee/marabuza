# Story-001 계산대 테스트 케이스

**스토리 유형**: Logic (계산 공식 + 상태 전이)
**증거 위치**: `tests/unit/save/` 또는 수동 실행 시 이 문서 (자동 유닛 테스트가 이미 있다면 그것이 우선 증거이며, 이 문서는 수동 회귀용 보조 증거)
**게이트 레벨**: BLOCKING

## 공통 사전 조건

- 서버 실행: `python3 -m http.server 8123 --directory src` 후 `http://localhost:8123` 접속
- 새 게임 시작 (타이틀 화면 → "게임하기")
- 공통 테스트용 그릇 구성 (표기가 없는 한 이 구성을 사용):
  - 청경채 ×1 (40g) + 숙주 ×1 (50g) + 옥수수면 ×1 (80g) + 어묵 ×1 (50g) = 총 220g
  - 저울 금액 = round100(220g ÷ 100 × 1,800원) = round100(3,960) = **4,000원**
- 소고기 × 양고기가 필요한 케이스는 별도로 다음을 선행한다:
  - DAY 1을 진행해 손님을 몇 명 응대하며 자금을 확보한다 (시작 자금 10,000원 + DAY 1 매출/팁)
  - DAY 1 종료 후 "상점으로 →" 이동, 재료 사기 카드에서 소고기 "🔓 해금" (6,000원), 양고기 "🔓 해금" (8,000원)을 각각 눌러 두 재료를 잠금 해제한다 (합계 14,000원 필요 — 자금이 부족하면 DAY 1에서 손님을 더 받아 매출을 늘린 뒤 재시도)
  - "DAY 2 영업 시작!"으로 새 영업일을 연다

## TC-001 — 정확한 청구 (exact)

**사전 조건**: 공통 그릇 구성(220g, 저울 금액 4,000원)을 대기 손님에게 조리·완성해 둔 상태
**단계**:
  1. 재료 선택 패널에서 청경채, 숙주, 옥수수면, 어묵을 각 1스쿱씩 담는다
  2. "조리하기!" 클릭 (또는 Space)
  3. 냄비가 완성되면 "완성! 서빙" 클릭
  4. 계산대 모달에서 "저울 금액 (자동)"과 "청구 금액"이 모두 4,000원인지 확인한다
  5. 추가 조작 없이 "청구하기" 클릭 (또는 Enter)
**기대 결과**: 계산대 모달의 "저울 금액 (자동)" = 4,000원, 초기 "청구 금액" = 4,000원. 확정 후 토스트에 "완벽해요! 😍" 또는 정확 청구에 해당하는 메시지와 청구액이 표시되고, 소지금이 4,000원 + 팁만큼 증가한다.
**판정 기준**: 청구 금액이 저울 금액과 정확히 일치한 채로 확정되고, 정확 청구(exact) 결과로 처리된다 (오버/언더차지 토스트 문구가 뜨지 않음).

## TC-002 — 초과 청구 (overcharge)

**사전 조건**: TC-001과 동일한 공통 그릇(저울 금액 4,000원)을 완성해 계산대가 열린 상태
**단계**:
  1. 계산대 모달에서 "+1,000" 버튼을 1회 클릭한다
  2. "청구 금액"이 5,000원으로 바뀌는지 확인한다
  3. "청구하기" 클릭
**기대 결과**: 정답가(4,000원)보다 1,000원 많은 5,000원이 청구·확정된다. 손해가 아닌 초과 청구로 집계되어야 한다 (평판/통계상 overcharge로 반영, 화면상 정확 청구 메시지가 아님).
**판정 기준**: 확정 시 청구 금액이 5,000원이며, 정답가 대비 +1,000원 차이가 overcharge로 처리된다(내부 상태 기준; 요약 화면에 아직 별도 표기가 없는 것은 정상 — story-004에서 노출 예정).

## TC-003 — 미달 청구 (undercharge)

**사전 조건**: TC-001과 동일한 공통 그릇(저울 금액 4,000원)을 완성해 계산대가 열린 상태
**단계**:
  1. 계산대 모달에서 "−1,000" 버튼을 1회 클릭한다
  2. "청구 금액"이 3,000원으로 바뀌는지 확인한다
  3. "청구하기" 클릭
**기대 결과**: 정답가(4,000원)보다 1,000원 적은 3,000원이 청구·확정된다. undercharge로 집계된다.
**판정 기준**: 확정 시 청구 금액이 3,000원이며, 정답가 대비 −1,000원 차이가 undercharge로 처리된다.

## TC-004 — 고기 추가 청구: 소고기 ×2 + 양고기 ×1

**사전 조건**: 공통 사전 조건의 "소고기·양고기 해금" 절차를 완료한 상태. 그릇: 청경채×1+숙주×1+옥수수면×1+어묵×1(저울분 220g/4,000원) + 소고기×2 + 양고기×1
**단계**:
  1. 재료 패널에서 위 구성대로 담는다 (소고기 2회, 양고기 1회 클릭 포함)
  2. "조리하기!" → 완성 후 "완성! 서빙"
  3. 계산대 모달의 "추가 재료 — 직접 더하세요" 목록에 "🥩 소고기 ×2"와 "🍖 양고기 ×1"이 모두 표시되는지 확인한다
  4. "+3,000"을 2회 클릭 (소고기분), "+4,000"을 1회 클릭 (양고기분) 하여 청구 금액을 4,000 + 3,000×2 + 4,000×1 = 14,000원으로 맞춘다
  5. "청구하기" 클릭
**기대 결과**: 저울 금액은 그대로 4,000원(고기 무게 미포함)이고, 정답가는 14,000원이다. 추가 재료 목록에 소고기×2, 양고기×1이 정확히 표시된다.
**판정 기준**: 14,000원으로 정확히 확정되면 exact 처리, 목록 표시가 실제 담은 수량과 일치한다.

## TC-005 — 고기 ×1도 수량 표기가 보이는지

**사전 조건**: 공통 사전 조건의 해금 절차 완료. 그릇: 공통 그릇 구성 + 소고기 ×1 (양고기 없음)
**단계**:
  1. 공통 그릇 구성에 소고기 1스쿱만 추가해서 조리·완성
  2. "완성! 서빙" 클릭
  3. 계산대 모달의 추가 재료 목록을 확인한다
**기대 결과**: "🥩 소고기 ×1"이 목록에 표시된다 (수량이 1이어도 ×1 표기가 생략되지 않음). 양고기 항목은 목록에 없다.
**판정 기준**: 목록에 정확히 "🥩 소고기 ×1" 한 줄만 있고 "×" 표기가 숫자 1일 때도 누락되지 않는다.

## TC-006 — 추가금 지우기 (초기화)

**사전 조건**: 공통 사전 조건의 해금 절차 완료. 그릇: 공통 그릇 구성 + 소고기 ×1 (저울 금액 4,000원)
**단계**:
  1. 계산대 모달을 연다
  2. "+3,000"과 "+1,000"을 각각 1회 눌러 청구 금액을 8,000원으로 만든다
  3. "추가금 지우기" 버튼을 클릭한다
  4. 청구 금액을 확인한다
**기대 결과**: 청구 금액이 원래의 저울 금액(4,000원)으로 정확히 되돌아간다.
**판정 기준**: "추가금 지우기" 클릭 직후 "청구 금액" 표시값이 4,000원이다.

## TC-007 — 청구 금액은 0원 미만으로 내려가지 않음

**사전 조건**: 공통 그릇 구성보다 가벼운 그릇 (예: 숙주 ×1, 50g → 저울 금액 round100(50/100*1800)=900원)을 완성해 계산대가 열린 상태
**단계**:
  1. 숙주 1스쿱만 담아 조리·완성 후 서빙 (저울 금액 900원)
  2. "−1,000" 버튼을 1회 클릭한다
  3. 청구 금액을 확인한다
  4. "−1,000"을 다시 여러 번 눌러본다
**기대 결과**: 청구 금액이 음수로 내려가지 않고 0원에서 멈춘다 (900원 − 1,000원 = -100원이 아니라 0원).
**판정 기준**: 어떤 조합으로 "−" 버튼을 눌러도 "청구 금액" 표시가 0원 미만으로 내려가지 않는다.

## TC-008 — Enter 키로 청구 확정

**사전 조건**: TC-001과 동일한 공통 그릇(저울 금액 4,000원)을 완성해 계산대가 열린 상태

**기대 결과**: 클릭 없이 Enter만으로 현재 "청구 금액" 그대로 청구가 확정되고 계산대 모달이 닫힌다.
**판정 기준**: Enter 입력 후 계산대 모달이 사라지고 소지금이 청구액+팁만큼 증가한다.

## TC-009 — 계산대 대기 중 두 번째 서빙 시도 차단

**사전 조건**: 상점에서 "냄비 추가" 업그레이드(3,000원)를 1회 구매해 냄비를 2개로 늘린 상태. 두 냄비 모두 완성되어 "완성! 서빙" 버튼이 보이는 상태
**단계**:
  1. 첫 번째 완성 냄비의 "완성! 서빙"을 클릭해 계산대 모달을 연다 (아직 청구하기를 누르지 않는다)
  2. 계산대 모달이 열린 채로, 두 번째 완성 냄비의 "완성! 서빙" 버튼을 클릭한다
**기대 결과**: 두 번째 서빙 시도는 무시되고 토스트 "계산대에 손님이 기다려요! 먼저 계산하세요"가 표시된다. 두 번째 냄비는 여전히 완성 상태로 남아 있고 계산대 모달의 내용(첫 번째 손님)은 바뀌지 않는다.
**판정 기준**: 토스트 문구가 정확히 표시되고, 계산대 모달이 첫 번째 손님 그대로 유지된다.

## TC-010 — 계산대 대기 중에는 영업일이 끝나지 않음

**사전 조건**: 영업 종료 시간(마감)에 가까운 상태에서 마지막 남은 손님의 주문을 완성해 서빙, 계산대 모달을 연 채로 둔다 (다른 대기 손님 없음)
**단계**:
  1. 계산대 모달을 열어둔 채 아무 것도 누르지 않고 상단의 영업 시계가 0에 도달할 때까지 기다린다
  2. 마감 이후에도 화면 상태를 관찰한다
  3. 계산대 모달에서 "청구하기"를 클릭한다
  4. 클릭 직후 화면을 다시 관찰한다
**기대 결과**: 2번 시점까지는 DAY 마감 요약 화면("DAY N 마감!")이 뜨지 않고 계산대 모달이 계속 표시된다. 3번에서 청구를 확정한 직후에야 비로소 마감 요약 화면이 나타난다.
**판정 기준**: 청구하기를 누르기 전에는 요약 화면이 절대 나타나지 않고, 누른 직후 곧바로 나타난다.

## TC-011 — 혼잡한 모달 레이아웃 (다수 추가 재료)

**사전 조건**: 공통 사전 조건의 해금 절차 완료. 그릇: 공통 그릇 구성 + 소고기 ×3 + 양고기 ×2
**단계**:
  1. 위 구성대로 담아 조리·완성 후 서빙
  2. 계산대 모달 전체를 확인한다 (⚖ 무게, 저울 금액, 추가 재료 목록, 가격 안내 문구, 청구 금액, +/− 버튼 6개, 추가금 지우기/청구하기 버튼)
**기대 결과**: "🥩 소고기 ×3", "🍖 양고기 ×2" 두 줄이 추가 재료 목록에 모두 표시되며, 목록이 늘어나도 모달 내 다른 요소(가격 안내, 청구 금액, 버튼들)가 화면 밖으로 밀려나거나 겹치지 않는다. 모든 텍스트가 잘리지 않고 읽힌다.
**판정 기준**: 추가 재료 2줄 + 안내 문구 + 버튼 8개(+1,000/+3,000/+4,000/−1,000/−3,000/−4,000/추가금 지우기/청구하기)가 모두 겹침·잘림 없이 화면에 보인다. (참고: 꼬치·고수는 현재 오리지널 플로우 UI에서 노출되지 않는 항목이라 이 케이스에서는 제외함 — story-003 범위)

## TC-012 — 주문과 크게 다른 그릇은 결제 거부 (계산대 자체가 열리지 않음)

**사전 조건**: 대기 손님 1명 선택, 손님 주문 말풍선의 재료·맵기를 확인해 둔다
**단계**:
  1. 손님 주문에 전혀 없는 재료 1스쿱만 담는다 (주문 재료는 하나도 담지 않는다)
  2. 맵기를 주문과 최대한 다르게 설정한다 (예: 주문이 2단계면 0단계 또는 4단계로 설정)
  3. "조리하기!" → 완성 후 "완성! 서빙" 클릭
**기대 결과**: 계산대 모달이 열리지 않는다. 대신 토스트 `"이거 제가 시킨 거 아닌데요?" 결제 거부 😡`가 표시되고, 손님이 즉시 자리를 떠나며 평판이 하락한다.
**판정 기준**: 계산대 모달이 전혀 나타나지 않고, 위 토스트 문구가 정확히 표시되며, 사이드바의 결제 거부/떠난 손님 카운트(😤)가 1 증가한다.
