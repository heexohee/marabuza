## 완료 조건

*`design/game-brief.md`(목표 & 실패 조건 + MVP 기능 2)에서 이 스토리 범위만 가져옴:*

- [x] 그릇의 총무게(g)는 담긴 "무게 재료"(채소·면·버섯 등 일반 재료)만의 합이다 — 고기와 꼬치류(꼬치, 새우)는 무게 계산에서 제외한다
- [x] 기본 가격은 `총무게 ÷ 100 × 100g당 단가`이고, 100g당 단가는 마라탕 1,800원, 샹궈 3,000원이다
- [x] 그릇에 소고기가 있으면 3,000원, 양고기가 있으면 4,000원이 추가된다 (둘 다 있으면 7,000원). 고기 무게는 총무게에 포함하지 않는다
- [x] 꼬치류는 1개당 1,000원씩 추가된다 (일반 재료처럼 무게로 계산하지 않는다). 새우 2개, 고급 어묵 3개, 고급 소시지 3개가 각각 꼬치 1개로 묶여 나간다. 그 외 꼬치 재료는 미정 — 이 3종만 우선 구현한다
- [x] 고수는 켜고 끄는 옵션이고, 선택하면 1,000원이 고정으로 추가된다
- [x] 사장(플레이어)이 청구 금액을 확정한다. 정답 가격보다 많으면 그 차액은 과다 청구로 기록된다 (스토리 004 정산에서 컴플레인 + 평판 하락)
- [x] 확정 금액이 정답 가격보다 적으면 그 차액은 손해로 기록된다 (매출 감소, 컴플레인 없음)
- [x] 정확히 맞으면 벌점 없는 정상 판매로 기록된다

## 예외 상황
- 빈 그릇 (0g, 재료 없음) — 가격 0원, 추가금 없음
- 고기·꼬치·고수가 모두 들어간 그릇 — 추가금이 모두 더해지고, 고기·꼬치·새우의 무게는 총무게에서 제외된다
  - 예: 무게 재료 300g(샹궈) + 소고기 + 꼬치 2개 + 고수 = 9,000 + 3,000 + 2,000 + 1,000 = 15,000원 (소고기·꼬치 무게는 계산에서 빠짐)
- 새우만 담긴 그릇(무게 재료 없음) — 총무게 0g이라도 새우 꼬치 개수만큼 추가금은 정상적으로 붙는다
- 청구 금액이 정답 가격과 정확히 같음 — 어느 쪽으로도 벌점 없음

## 구현 메모

이 단계에는 ADR이 없으니, 위 완료 조건과 브리프의 가격 공식대로 바로 구현한다:

```
총무게 = Σ(무게 재료의 그램수)   ※ 고기·꼬치(꼬치, 새우)는 제외

가격 = (총무게 / 100) × 100g당단가(마라탕 1800 | 샹궈 3000)
     + (소고기 포함 ? 3000 : 0)
     + (양고기 포함 ? 4000 : 0)
     + 꼬치개수 × 1000          ※ 새우는 2개 = 꼬치 1개로 환산
     + (고수 ? 1000 : 0)
```

| 항목 | 가격 | 무게 계산 |
|---|---|---|
| 마라탕 100g당 | 1,800원 | — |
| 샹궈 100g당 | 3,000원 | — |
| 소고기 추가 | 3,000원 | 총무게에서 제외 |
| 양고기 추가 | 4,000원 | 총무게에서 제외 |
| 꼬치 1개 | 1,000원 | 총무게에서 제외 |
| 꼬치류(아래 표) 1개 | 1,000원 | 총무게에서 제외 |
| 고수 추가 | 1,000원 | 해당 없음 (무게 재료 아님) |

**꼬치류 재료 (모두 꼬치 1개 = 1,000원, 무게 계산 제외)**

| 꼬치 재료 | 꼬치 1개당 개수 |
|---|---|
| 새우 | 2개 |
| 고급 어묵 | 3개 |
| 고급 소시지 | 3개 |
| *(그 외)* | **미정 — 추후 확정 필요** |

가격 값은 코드에 직접 쓰지 말고 `src/js/data.js`의 상수로 둔다. 꼬치류 재료는 다른 재료처럼 그램 단위로 재고를 다루지 말고, "꼬치 개수" 단위 재고로 취급한다 — 이 부분은 `src/js/data.js`의 재료 정의를 다시 분류해야 함을 의미한다 (무게 재료 / 고기 / 꼬치류 세 종류). 위 표에 없는 꼬치 재료는 이 스토리 구현 시점까지 확정되지 않으면, 지금 확정된 3종(새우·고급 어묵·고급 소시지)만 구현하고 나머지는 후속 스토리로 미룬다.

**성능**: 성능 영향 없음 — 재료 몇 개짜리 작은 그릇 객체를 단순 계산하는 것이고, 매 프레임이 아니라 계산할 때 한 번만 실행된다.

지금 `src/js/logic.js`의 `bowlPrice`는 무게 × 100g당 단가 하나만 계산한다. 이 스토리에서 이를 대체한다. 기존 코드 방식대로 순수 함수로 유지한다 (상태를 받아 새 상태를 반환). 참고할 패턴: `src/js/logic.js`의 `scoreBowl`, `servePot`.

"사장이 금액을 확정하는" 단계는 공식이 아니라 새 UI/조작이다. **(2026-09-25 사용자 결정)** 소고기·양고기 추가금은 담은 개수만큼 곱한다(소고기 ×2 = 6,000원). 청구서에는 1개라도 "소고기 ×1"처럼 개수를 표시한다. **(2026-09-24 사용자 결정)** 계산대는 저울 금액(무게 × 100g당 단가)을 자동으로 찍어 보여주고, 사장은 고기·꼬치·고수처럼 단가에 포함되지 않는 추가 재료 금액만 직접 더해 청구한다. 플레이어가 정답 가격과 별개로 청구 금액을 입력하거나 조정할 수 있어야, 과다/과소 청구를 비교할 대상이 생긴다.
