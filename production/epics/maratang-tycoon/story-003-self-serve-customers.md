## 완료 조건

*`design/game-brief.md`(핵심 루프의 셀프 담기 단계 + MVP 기능 1)에서 이 스토리 범위만 가져옴:*

- [ ] 새 손님은 진열대에서 이미 재료를 담은 그릇을 들고 온다 (지금 코드처럼 플레이어가 한 스쿱씩 담는 방식이 아님)
- [ ] 그릇을 채운 만큼 진열대 공용 재고가 줄어든다 (상태의 다른 곳에서도 쓰는 같은 `stock` 맵)
- [ ] 어떤 재료의 진열대 재고가 0이면, 새로 생성되는 손님 그릇에 남은 재고보다 많이 담길 수 없다
- [ ] 생성된 그릇은 계산대(스토리 001)로 넘어가 가격을 매길 수 있는 형태다 — `bowlPrice`/`scoreBowl` 계열 로직이 기대하는 구조와 같음
- [ ] 손님은 인내심 타이머를 가진다. 사장이 제때 계산해주지 않으면 떠난다 (`src/js/logic.js`에 이미 있는 대기/이탈 방식을 재사용)
- [ ] 여러 손님이 동시에 줄을 설 수 있고, 각자 이미 채운 그릇과 독립된 인내심 타이머를 가진다

## 예외 상황
- 그릇을 생성하는 도중 재료 재고가 정확히 0이 됨 — 생성 시점의 남은 재고를 지켜야 함
- 손님 여러 명이 연달아 와서 재고가 적은 같은 재료를 두고 경쟁함

## 구현 메모

이 단계에는 ADR이 없으니, 위 완료 조건대로 바로 구현한다.

지금 코드에서 가장 크게 바뀌는 부분이다. 현재 `src/js/logic.js`의 `generateOrder`는 *희망 목록*(플레이어가 담아야 할 것)을 만들고, 플레이어가 `addScoop`/`removeScoop`으로 직접 그릇을 채운다. 이 스토리에서는 반대로, 손님 그릇이 처음부터 채워진 채 생성된다 (여전히 `stock` 안에서만 — `addScoop`의 재고 차감 방식을 재사용). 플레이어의 일은 그릇 채우기가 아니라 계산(확인하고 가격 매기기, 스토리 001)으로 바뀐다.

기존 인내심 타이머와 "손님이 떠남" 로직(`src/js/logic.js`의 `tick`, `departCustomers`)은 그대로 둔다. 바뀌는 건 그릇을 채우는 단계뿐이고, 기다리고 떠나는 동작은 같다.

**성능**: 성능 영향 없음 — 손님이 올 때 한 번, 재료 몇 개를 고르는 계산이다.
